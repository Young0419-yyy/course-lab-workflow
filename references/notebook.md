# Notebook 运行与核验

## 环境选择

先发现用户环境中的 Python（Windows 可查看 `Get-Command python` 和 `py -0p`），再运行候选解释器输出 `sys.executable`、`sys.version`、`sys.base_prefix`。检查已有 `.venv/pyvenv.cfg` 和环境解释器能否启动；文件存在并不表示环境有效。失效时优先新建本次实验自己的环境，保留其他实验使用的环境。

依赖安装使用 `<虚拟环境 Python> -m pip ...`，避免命中全局 pip。按实验所需选择兼容版本；不要照搬某次实验的固定版本。运行 `pip check` 和实际导入核验，而不只看安装命令退出。

当前实验的解释器来自用户本机 Python。PDF 读取、文档排版等辅助工具可以使用平台提供的运行时，这与实验解释器分别处理。

## 不依赖 Jupyter 保存真实输出

随附 `scripts/execute_notebook.py` 仅使用标准库和实验中已经安装的绘图库、表格库。它从头依次执行代码，模拟普通 Python 单元格最后一个表达式的展示；捕获标准输出、错误输出和 Matplotlib 图像，成功后原子保存 Notebook。

脚本是内部制作工具，不粘进学生 Notebook，也不需要复制到实验目录。它会实际执行代码，使用前检查所有单元格是否属于用户授权的实验。遇到非普通 Python 语法、依赖缺失或运行失败时，按真实报错解决，不伪造输出或吞掉错误。

工作目录默认是 Notebook 所在目录，也可通过 `--cwd` 指定。数据路径围绕实验目录设置，避免硬编码用户名、盘符或其他实验名称。读取 CSV 时显式处理指导材料中实际存在的表头问题。

脚本保留 Notebook 现有元数据并记录当前 Python 版本；这不等于已经在 VS Code 选择内核。默认通过实际解释器路径、环境配置、工作区设置和 Notebook 元数据核验，不使用 Computer Use 检查 VS Code，也不要求截图确认窗口或操作内核选择菜单。若本次要求确实需要额外核验，可委派 `gpt-6.1-terra`；只有命令和文件证据不足时才考虑必要的界面核验。只打开已保存的输出不需要启动内核或安装额外依赖。

## 科学性检查

- 对照 PDF 和批注逐项核对映射；检查缺失值、无效标签及数据总量。
- 按实验性质选择验证方式；关联规则、描述统计等任务不机械加入测试集。
- 对监督任务核对训练、验证和测试索引隔离；采样只接触训练数据。
- 用同一选择规则比较各候选模型。比较表说明验证集与测试集指标，不把测试集排序结果用于反向调参。
- precision 等分类指标按明确标签顺序解释混淆矩阵；回归、聚类、关联规则使用本次要求的指标。
- 图表中的标题、坐标和中文正常显示，数字与实际报告一致。
- 未达到“同时提升多个指标”时直接说明实际取舍；不为满足措辞改标签、删样本、换随机种子或捏造数值。

## 验收

确认代码单元格按顺序运行、执行序号完整、输出真实保存；检查错误输出及警告，修正实际问题。核对指标能从原始预测结果重新计算，Notebook 结论与展示输出一致。用户没有要求的独立代码文件、测试目录和导出图不作为实验成果保留。
